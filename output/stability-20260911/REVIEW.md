# 模块耦合与前端轻量化稳定性审核

日期：2026-09-11。工作区：`D:\E2EAPP_MicroMani`。

## 结论

确实存在单模块失败向其他模块传播的路径。本轮已复现并修复共享 UI 崩溃、坏遥测污染共享状态、异步旧响应覆盖、相机告警漏更新、后端遥测串行汇合点失败，以及 HAL 控制回调和 HTTP 线程管理缺陷。

当前隔离仍以组件、请求和 C++ 异常边界为主，尚未做到任意线程或驱动崩溃时其他模块完全不受影响。尤其是 HAL 驱动共用进程、前端共用 JavaScript 主线程，以及后端阻塞调用共用线程池，仍是需要区分的共同故障边界。安全控制出现未预期异常时，允许触发全局锁存停机；不能为维持其他模块继续运动而绕过安全状态。

本轮保留工作区原有改动，未提交、部署、启动或操作实机。所有浏览器验证均拦截 API 和 WebSocket；后端测试使用替身，HAL 测试未初始化真实设备。

## 模块间故障传播检查

| 模块/汇合点 | 已确认的传播或不稳定点 | 本轮处理与边界 |
| --- | --- | --- |
| 页面路由及懒加载 | 页面异常需要与导航、急停隔离 | 保留既有 RouteErrorBoundary，并验证页面/lazy 加载失败时外壳仍在 |
| 顶部/底部状态、日志、安全提示、全局急停显示 | 共享外壳没有逐模块边界，一个渲染错误可卸载整个界面 | 分别设置 ModuleErrorBoundary；急停显示报错时保留直接调用急停动作的原生按钮 |
| WS → Zustand → 全部订阅者 | 未验证的网络对象进入共享 frame/log，多个模块同时收到坏结构 | 在接收入口验证主结构；坏帧不进入状态、不刷新安全新鲜度，清理待显示帧并阻断控制确认；后续合法帧可恢复遥测 |
| 遥测节流与力急停 | 普通渲染节流不能延迟明确的锁存信号 | 先处理显式 `safety.latched === true`，即使同帧其他字段损坏也保持本地急停意图；合法帧恢复不自动解除该意图 |
| 连接初始化/PICO 检测 | 断开后旧请求仍回写，PICO 响应携带的整份旧配置可覆盖其他新参数 | 增加连接代际和配置归属校验；PICO 仅更新其负责的配置段；WebSocket 构造失败转为可见离线状态 |
| 相机切片订阅/预览告警 | `camerasEqual` 忽略 `timestampSkewMs`，仅时钟偏差变化时预览告警不更新 | 比较补齐时钟偏差、标签及 backend；实际 hook + CameraPreview 回归覆盖从正常到偏差告警的更新 |
| Model / FineTune | 请求拒绝未处理、旧请求覆盖、重复提交、卸载后继续刷新 | 捕获并显示错误，提供重试，使用请求序号及在途锁；保留 Stop / Cancel 入口 |
| Dataset | 请求失败仍显示删除/修改成功；不同数据集同名 episode 的状态互相污染 | 成功后才应用修改；使用 datasetId + episodeId；失败可重试、迟到详情不能覆盖新选择 |
| 轻量 UI / Canvas 图表 | 检查 disabled 传递、Canvas context 和 ResizeObserver 清理 | 未找到足以确认的新崩溃缺陷，未作推测性改写；没有宣称覆盖所有输入组合或性能极限 |
| 后端 WS 组帧 | 夹爪状态读取在运动/力帧和日志发送之前失败，会阻断整条通道 | 在夹爪边界局部降级为明确不可用状态，保留运动/力遥测与日志；故障恢复后正常出帧 |
| 后端 HAL 健康缓存 | 首读失败会退出并漏清客户端；刷新失败继续显示旧健康 | 首读移入保护循环，失败立即离线，成功恢复，客户端由 finally 清理 |
| 后端退出清理链 | 某任务或相机清理失败，跳过后续资源释放 | 逐项捕获并记录，继续独立资源清理；不能中断永久阻塞的 SDK 调用 |
| HAL Native 主控制/夹爪及映射回调 | 标准异常后继续控制，非标准异常可逃出线程入口 | 异常进入锁存停机，分别尝试运动停止、待执行命令清理、Omega 力关闭；停止相关循环并保留诊断 |
| HAL 力安全回调 | 停机回调异常向共享采样/监控调用链传播；前一步失败会漏掉后续停机动作 | 各停止动作都尝试；异常被记录并保留力锁存，回调失败时拒绝普通 ACK 恢复 |
| HAL HTTP 诊断连接 | 无界 detached 线程、创建失败逃逸、发送缺少超时 | 最多 32 个可回收 worker，异常释放连接和槽位，检查收发超时设置；未进行真实 TCP 负载测试 |

## 与近期前端优化的关系

能够直接定位到优化实现的问题是相机切片比较漏掉告警字段：减少重渲染时将仍被页面使用的字段视为无关，导致显示停留在旧值。修复前的回归能重现，修复后显示随偏差变化更新。

轻量化后的共享状态和外壳中还确认了坏数据、懒加载/网络失败及请求生命周期的问题。本轮按当前实现修复，不把所有问题都归因于轻量化。后端 WS 串行汇合和清理链缺陷在 `HEAD` 基线中同样存在；HAL 控制回调及无界 HTTP 线程也属于原有结构问题。CSS 缩放不是本轮这些线程或状态故障的成因。

## 尚未消除的风险与验证缺口

1. **HAL 仍有共享进程故障风险。** `MotionControlThread::loop`、HKVL `runSide`、Force `monitorLoop`、DDS 普通/急停轮询入口尚未完整包裹所有异常源。本轮修复了已复现的回调异常源；其余入口和驱动 DLL 的访问违规、内存破坏或系统层故障仍可能终止整个 HAL。具体位置见 HAL 报告，不能把 C++ 回归通过解释为全部线程隔离。
2. **永久阻塞没有被 try/catch 解决。** 后端共享线程池中的 SDK 调用、HAL 持锁调用或 HTTP dispatcher 若永久不返回，仍可能耗尽资源或阻止退出。HTTP 限流限制了新连接并发，不能强制终止内部设备调用。
3. **前端主线程仍共享。** React ErrorBoundary 可隔离渲染异常，不能恢复无限循环、浏览器卡死、内存耗尽或页面进程退出；这种情况下页面内急停按钮也无法响应。必须保留执行侧保护，不能由前端可点击状态代替。
4. **设备链路未验收。** 本机缺少配置所需的 `F:/opt/ros/jazzy` DDS SDK；本轮 DDS listener/publisher 护栏只有源码检查。未验证真实 DDS/USB 故障、驱动崩溃、物理急停响应时间及碰撞风险，不将离线结果视为实机安全保证。

后续最关键的验证对象是上述进程级故障和永久阻塞路径；本轮没有自动增加进程拆分、强杀线程或实机故障注入。
