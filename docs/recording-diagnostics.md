# 录制卡顿诊断

正常录制默认关闭逐帧诊断及线程栈采样。编码丢帧检测和禁止保存缺帧 episode 的保护始终生效。

运动状态统一使用完整读卡结束时的时间：JSON 的 `timestamp_ms` 与 DDS 信封的
`stamp_unix_ms` 为同一读卡 Unix 时间，`stamp_monotonic_ms` 为同次读卡的单调时间。
重复发布或读取缓存不会刷新这些时间；30 Hz 选样和 `origin_move` 使用读卡单调时间，
有效期从读卡 Unix 时间计算。字段名保持不变，不另存运动状态的 DDS 发布时间。
后端拒绝信封与读卡时间不一致的旧 HAL 消息；启用此修改须同步构建、部署
`HalServer.exe` 与 `JodellGripperWorker.exe` 并重启相关服务。历史数据不会自动修正。

`origin_move` 复用现有 HAL 采样循环，不另起循环或定时器，也不再按 100 Hz 二次抽样。
对齐缓存按时间或容量淘汰样本时，将样本按读卡时间交给既有有界写队列；重复读卡时刻
只写一次。写线程以最多 256 个样本的小批次追加临时 Parquet，不在内存保留整段历史。
保存时补写缓存尾部，native episode 保存成功后才封口；丢弃或写入失败时清理临时文件，
不会把缺块旁路文件发布为完整结果。上游最新状态缓存已经覆盖的硬件样本无法由此补回。

需要排查时，在启动后端的 PowerShell 中设置环境变量，再从同一终端启动应用：

```powershell
$env:APPSTATION_RECORDING_DIAGNOSTICS = '1'
```

每个采集会话启动后最多记录 180 秒，文件位于 `backend/runtime/record-trace-*.jsonl`，独立于训练数据。记录采样时间、选帧时间戳、组帧和写入耗时、编码队列、超过 10 毫秒的垃圾回收停顿，以及每约 100 毫秒一次的 Python 线程栈；不记录图像和局部变量。

诊断结束后，将变量设为 `0` 并重启后端，恢复正常录制模式。设置环境变量不会改变已经运行的后端。既有诊断文件保留，可用于科研对照。
